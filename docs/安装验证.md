# 安装与验证边界

本页说明「装上了」「工具能调用」「模型会用」分别靠什么证据，避免把其中一项当成另一项。
安装命令见 [README](../README.md#接入两种方式二选一)。

## 环境要求

| 项 | 要求 |
|---|---|
| Node.js | **≥ 20**（用到全局 `fetch`、`AbortController`）；已在 Node 22、24 上验证 |
| npm | 随 Node 提供即可（`npm ci` 需要 npm 7+） |
| 网络 | 本地 stdio 方式需能直连各数据库；不要求代理 |
| DSH（可选） | 仅插件形态需要；只使用 MCP 的客户端不需要装 DSH |

## 从源码验证

```bash
npm ci
npm run check
```

`npm run check` 依次执行：类型检查 → 离线测试 → 构建 → 数量闸 → 站点闸 → 措辞闸 → 预算统计 → 契约闸。
全程离线（fixture 回放），退出码 0 表示这套检查全部通过。任何一道失败都会非零退出。

常用单项：

```bash
npm run typecheck     # 类型
npm test              # 离线用例（不联网）
npm run build         # tsc + 客户端 bundle
npm run stats         # 源数 / 工具数 / 预算
npm run counts        # 数量事实（--json 输出机器可读结果）
npm run doctor        # 已装插件 vs 仓库构建的漂移检查（需先 build）
```

## 起一个本地服务并调用

```bash
npm run build
npm run serve                     # 默认 http://127.0.0.1:8971/mcp，不鉴权
curl -s http://127.0.0.1:8971/healthz
```

`/healthz` 返回 `status`、`version`、`sources`、`tools`、`metaTools`。要绑定非回环地址时必须设置
`PLANTOMICS_HUB_TOKEN`（至少 16 字符），否则服务拒绝启动。

首次真实调用建议用两个稳定示例：

- `gwh_assembly_lookup`：`entity=assembly`、`id=GWHAAAA00000000`
- `icg_lookup`：`entity=species`、`id=ICG00115`

检查结果末尾的出处行：源、完整请求 URL、HTTP 状态、耗时、查询时刻。再问一个未被覆盖的问题，
确认工具如实说「没有覆盖」，而不是拿别的物种数据凑答案。

## 已验收到哪一层

| 层 | 证据 |
|---|---|
| 依赖可复现 | `npm ci` 按 `package-lock.json` 安装 |
| 源码可构建 | `npm run check` 退出码 0（含类型检查、构建与全部门禁） |
| 工具可调用 | 离线 fixture 回放 + 上面的真实示例 |
| 上游可达 | `npm run probe` 单独测；不放进离线测试 |
| 宿主端到端 | 需要在目标客户端里实际配置并重启，本仓不代做 |

## 不作承诺

- 不承诺所有上游长期可用；上游维护、限流或网络不可达时，工具会明确报错。
- 不在离线测试里访问真实网络，因此「测试全绿」不等于「上游现在可达」。
- 不同 Node.js 小版本、不同操作系统与不同 MCP 客户端未逐一实测。
- 本仓不包含任何凭据；本地服务需要鉴权时由使用者自行生成 token。
