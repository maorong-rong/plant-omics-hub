**SCOD 要点**（2026-10-29 实测，共 13 次请求）：

- **定级 T2**：有参数化 URL、四个端点实测 200 JSON，但拿不出 API 文档地址，够不上 T1。
- **区间语义：整条基因完全落在区间内才返回**。决定性反例 `posStart=130574&posEnd=133000` → 0 条（目标基因 130574–133277 终点越界）；`131000-136000` 与基因明显重叠却 0 条，因此**不是"按起点"也不是"任意重叠"**。
- **`length` 必须本地限 ≤ 50**：`length=1000` 实测 2.0 MB / 45.6 秒，超过 20 秒上游超时；默认 10 条、`length=50` 为 112 KB / 2.6 秒。
- **两套信封并存**：`genome/list` 是裸数组，`gene_list` 是 DataTables `{draw, recordsTotal, recordsFiltered, data}`；`recordsTotal` ≠ `data.length`（分页时 11 vs 2）。
- **`posStart`/`posEnd` 是字符串**（`"130574"`），不是数字。
- **染色体命名是 `Chr1A`（大写 C）**，这是本仓遇到的第三套命名。
- **0 条不等于"该位置没有基因"**：窄区间包不住基因终点时会静默返回 0，属完全包含语义的正确结果，但对用户是陷阱，正文必须提示。

### WheatOmics 端点编号代次（01G / 02G / 03G）——逐端点登记（2026-11-10）

> **为什么要单列**：2026-11-10 一天内出现多例同源问题——`gene_detail` 与 Pfam 表对同一基因给两套坐标（差 1.34 Mb）；302 个 03G 成员在 `cross_species_homologs` 全回 0；共线表只认 01G；GO 富集 03G 直送 `n=0` 且 0.6 s 返回。它们不是「工具坏了」，而是**同一平台的不同端点各用一代编号，且没有端点声明自己用哪代**：查询不报错、只返回 0，静默出错。⇒ **「返回 0」在 wheatomics 端点上不能解释为「没有数据」。**
>
> 本节只做**事实登记**：代次与依据都来自仓库内已有证据（文件:行 / E 编号 / PR 回执）。**查不到的写「未知」，并写清试过什么、为什么判不了，不推断。** 本节**不产出新的缺口编号**——仓库里已有三份同名不同义的 G 编号，另有并行单在出缺口报告 v2；本单若发现新缺口，只记「待 v2 登记」，不自己造 G-x。
>
> 两条口径先记住：
> 1. 「01G/02G/03G 前缀」与「v1/v2/v3 叫法」不是一一对应，**组装版本、注释版本、站点内部映射表是三件事**；上文「版本口径」段已定：只转述上游，不按 ID 外观推断。

### 「静默返回 0」排查清单（wheatomics）

> 目标：在写「没有数据」之前，按顺序走完五步并留证。每一步都写明**能排除什么**、**排除不了什么**。
> 反例（本清单的由来）：302 个 03G 送 GO 富集 `n=0` 且 0.6 s 返回，看起来像「没有 GO 注释」；同一 4 个基因换 `02G+.1` 后 `n=4` / `results=136`（PANELS-6-11:218-231（私有仓记录，未公开））。⇒ 0 不是生物学 0。

1. **对代次**：查上面的代次表，确认输入 ID 前缀是否是端点认的那代；端点代次未知时，这一步什么也排除不了，必须做第 2 步。**能排除**：用错代次——这是最常见的一种静默 0。
2. **换代次复测**：同一基因换 02G（GO/PPI 再加 `.1`）、01G（共线表）各打一次。**能排除**：编号不识别 / 映射缺失（例：302 个 03G → 0，换 `02G+.1` → 4）。**排除不了**：端点整体故障（交给第 3 步）。
3. **已知阳性对照**：同一次排查里，用该端点已知有结果的基因回显（例：同源端点用 02G `TraesCS5A02G391700` → **6 条**，wheat-mads README:356-357（私有仓记录，未公开））。**能排除**：工具 / 网络 / 上游整体不可用（阳性对照也 0 才是这一类）。**排除不了**：表键 / 区间语义（交给第 4 步）。
4. **区间 vs 单基因**：把基因坐标换算成区间再查（例：`/synteny/search` 单基因 03G → 0、同基因区间 → 2；E07 区间 → 40）。**能排除**：单基因入口 / 默认表键问题（共线表按 01G 建键）。**排除不了**：上游确实未收录该基因。
5. **才判「上游没有」**：前四步都留证（代次、对照 ID、区间、HTTP 状态 / 耗时 / 字节）后，只能说「**本次未取到**」，并写明代次与端点；仍**不写「不存在」**。**能排除**：把静默 0 当生物学 0 的结论性错误。

## 六、Gramene 接入边界

- 四个工具对应四个意图：全文检索（`q`）、基因、差异表达、分类单元。`/search` 用 `q`，其余只收 `idList`；`q` 传给非 search 端点只会得到空数组。
- **`idList` 是数组参数**：数值型单值 `idList=4530` 实测返回 400（`Expected type array but found type integer`）；本仓对单值也重复发送一次并按 `_id` 去重，输出注明该规避写法。
- **身份对账**：返回 `_id` 不在请求集合内即抛"身份不符"；请求了未返回的 ID 逐个列出，不写成"不存在"。
- **`/search` 的 content-type 是 `text/plain`**，正文是 JSON；本仓按正文解析，不按 content-type 分流。
- 查无 = HTTP 200 + 空数组（`/search` 为 `numFound=0`）；`start` 越过末页单独报"已越过末页"，不与无匹配混为一谈。
- 覆盖只写实测：`Oryza sativa`（4530）、`Oryza sativa Indica Group`（39946001），不外推禾本科。版本口径只写 v69，与 Ensembl 版本对应关系未核验。
- 裁剪：单基因原 8.5 KB 含 `xrefs`，工具不返回；表达每实验最多 3 个、每实验 2 个比较；`facet_counts` 不读、`ancestors` 只给长度。
